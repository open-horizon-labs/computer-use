# Facade vs. native A/B evidence — 2026-09-28

One bounded run per arm (facade `cua-task` MCP vs. native `cua-driver` MCP), same driving model (Opus), same two fixture tasks (a 12-record booking list, an orders table with a cancel-confirm step). Directional evidence from a single run per arm, not a benchmark: sample size is one, and the user suspects some observed failures may have been caused by the user moving windows/Spaces mid-run rather than by the facade itself (see the `off_space_or_ax_unresolved` finding below, which is independently corroborated by the driver version). Treat this as a bug list the fixes below address, not a calibrated win/loss score.

## What was observed

- **Semantic `cua_choose` without a reading** sent the Jev/Julia chooser candidates whose descriptions were just `"Book"` × 12, indistinguishable from each other. The chooser deferred (reobserve, ~0.49 score) while the native agent won because the raw AX tree gave it row context for free.
- **Visual mode (`mode='visual'`) returned `action_authorized: true` for the wrong button twice** — a different provider's "Book" (record `e64`), and the organizer row's "Cancel" instead of the intended row's. Its `evidence` string was just `"Book"`. Only the driving agent's own judgement stopped the click from being executed.
- **The driving agent wrote the answer into the goal** ("The correct one is ... → e56", "Earliest is 3:00 PM → e56") and narrowed `candidate_ids` to its own preselection; the chooser then rubber-stamped it rather than evaluating evidence.
- **Predicate ops `ne`, `not_contains`, `contains`** were attempted and rejected with an opaque "unsupported predicate"; the matcher only implemented `eq`/`neq`/`gt`/`gte`/`lt`/`lte` and the MCP schema didn't list any allowed ops.
- **Repeated `{"status":"defer","route":"nuextract3","reason":"unknown_or_incomplete_scope"}`** with no detail on which records were unknown or why; the agent guessed three times before giving up on that path.
- **`cua_verify(mode='exact')` errored** "Driver did not return a bound snapshot" (window gone, or a Driver issue) with no way to tell which; **visual verify returned `unknown`** on a visibly correct status line ("Booked: Dr. Morgan Reyes, half-hour, 3:00 PM") that a deterministic text check would have caught immediately.
- **A window on another macOS Space**: cua-driver 0.28.2 reported `background_input.exact_window.status: ax_unresolved` and refused routes with reason `off_space_or_ax_unresolved`. This is fixed upstream in cua-driver ≥ 0.29.1 ([trycua/cua#4068](https://github.com/trycua/cua/issues/4068)). A window closed mid-task separately produced the same vague snapshot error as above.
- One agent sent a `cua_act` with a placeholder handle in parallel with `cua_choose` — the facade already rejected that correctly (unknown/already-consumed selection); no change needed there.

## The eight fixes

1. **Record context in candidate descriptions** — each offered action's description now includes the text of its smallest disambiguating ancestor subtree ("record"), never a sibling's or the whole list's text. `facade/core.py:Facade.record_context`, wired into `Facade.actions`.
2. **Visual choice cannot authorize alone** — a visual pick is only issued a selection handle when corroborated by a complete filtered `reading` or by deterministic quoted-text matching against record context; otherwise `status: defer`, `reason: visual_uncorroborated`, non-executable `suggested_id`. `Facade.visual_corroborated`, wired into `Facade.choose`.
3. **Reject answer-leaking goals** — a `goal` naming an observed element ID or stating the answer ("the correct one is ...") is rejected with a `Gap`; a caller-narrowed `candidate_ids` subset with no `reading` is flagged `caller_preselected` in the result and trace instead of counting as chooser accuracy. `Facade.reject_answer_leak`, `Facade.choose`.
4. **Discoverable predicates** — `contains`/`not_contains` (text-only, case-insensitive, whitespace-normalized) and `ne` as an alias for `neq`; the unsupported-op error lists every allowed op; the MCP schema types `op` as a `Literal`. `inference/cua-decider/capability-dispatch/dispatch.py:predicate`, `facade/server.py:Predicate`.
5. **Actionable incomplete-scope defers** — `unknown_or_incomplete_scope` now carries `unknown_ids`, `eligible_ids`, `excluded_count`, per-unknown-record `missing_fields`, and a `hint`. `Facade.incomplete_scope_defer`.
6. **Verification** — exact `match: 'equals'|'contains'`; a specific `window_closed` vs. `driver_snapshot_unavailable` (with the Driver's refusal/degraded detail) Gap replacing the vague snapshot message; visual verify checks any `"quoted"` postcondition text against the fresh AX tree first and only falls back to the vision model when that text isn't found. `Facade.observe`, `Facade.verify`.
7. **Spaces / foreground / driver version** — `cua_act` refuses with `needs_foreground` before delivery when `background_input.exact_window.status` isn't `matched` or a route was refused `off_space_or_ax_unresolved`; the facade never activates/raises/moves a window to work around it. The Driver's version is detected once (`<driver> --help`) and tool startup is refused below `0.29.1`; `driver_version` is now reported in `cua_trace`/`cua_finish`. `Facade.check_foreground`, `Driver.version`, `Facade.windows`.
8. **Non-disruptive A/B harness** under `experiments/facade-vs-native/` reproducing the booking/orders fixtures, a `/log`-backed ground truth, and a runner/scorer for repeatable, consented, desktop-operating comparison runs. Not run as part of this change; see its README for consent requirements.

Fixes 2 and 3 are policy additions (not just projection repairs): the user explicitly authorized "fix all" of the above on 2026-09-28, so they proceeded as authorized policy changes rather than waiting for a separate approval step.

## Verification

Each fix has at least one regression test in `facade/test_core.py` or `inference/cua-decider/capability-dispatch/test_dispatch.py` that fails against the "tempting wrong patch" named in the corresponding commit/PR description — see those test names for the mapping. The full offline gate (`facade` + `inference/cua-decider` unit tests, `simulation_gate.py`, `check_protocol.py`, `sync_skill_references.py --check`) passed after these changes; no desktop, model worker or network endpoint was used to validate them.
