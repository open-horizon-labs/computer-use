# Isolated computer-use recovery and client bakeoff — 2026-10-01

The updated MCP runtime is installed locally as `computer-use-oh` in Claude Code and Codex. New tasks default to non-OBO; OBO intent is a per-task MCP context, not an environment variable. The user explicitly skipped further OBO live testing while the desktop was locked. The completed comparisons use isolated browser sessions on this Mac's virtual displays; no real account workflow was exercised.

## Method and limits

The tasks are the existing neutral booking, order-cancellation and duplicate-Save fixtures. The native arm is stock Cua Driver MCP; the stack arm is Open Horizons `look`/`do` MCP over the same Driver. The agents receive the same task intent and must verify the visible result. Claude exposes only the selected MCP server; Codex is configured with only that server and prompted to use it exclusively. Server-side fixture events determine correctness and wrong actions independently of agent self-report. A run must complete the whole expected event sequence without a forbidden action to count as correct.

This is exploratory bug-finding evidence, with one run per client/model/task/arm in each phase, not a preregistered accuracy verdict. Earlier failures and later reruns are separate phases; they are not silently replaced. Native-skill, canvas, native file pickers and real authenticated workflows were not tested. Semantic DOM operation while locked does not establish that native foreground input or pixels work while locked. Raw transcripts remain local because Driver inventory can include private window titles; the retained results contain only synthetic-task metrics and events.

Claude cost is the client's reported API-equivalent USD, not a subscription charge. Codex exposes aggregate token usage and completed MCP calls; its internal LLM turn count and API-equivalent USD remain unknown. Wall time includes opening the isolated browser, model deliberation, tool calls and verification. These measurements cannot isolate the local selector's accuracy or cost.

## Repairs from observed failures

- Claude silently omitted the configured server named `computer-use` in this tested CLI setup. Renaming it `computer-use-oh` connected successfully; the harness now treats a missing MCP server as launcher failure.
- Codex's fixture calls were blocked before reaching the runtime by tool approval policy. Local approval is scoped to this server's `look` and `do`; benchmark approvals are scoped to the selected arm server.
- Native AX was unreadable while an exactly bound isolated browser could still supply complete semantic DOM evidence. The facade now accepts that source, retains binding and fresh verification, and avoids repeating futile AX probes after a successful fallback.
- Repeated labels require a fresh scoped ref with an unchanged observed record. Unlabeled table rows use a bounded read-only scope search, with content matching rather than an action chosen by ordinal. Cell text now follows the facade's existing displayed-line contract.
- Dialog execution incorrectly required the entire offered action set to contain one action. It now rebinds exactly the selected action from the offered set, including when the desired action is not first.
- An explicit isolated URL lookup could inspect the user's Chrome and attempt profile preparation. It now searches only its owned browser, and every URL lookup is read-only. A missing isolated page gives a navigation hint instead of a user permission request.
- Driver's full and scoped form outlines appended editable shadow nodes below missing parents, making an unchanged form appear changed. The parser preserves these as separate roots, never invents ancestry, and still refuses changed real field values, unparsable evidence or ambiguous controls.
- The order fixture logged successful cancellation but left its row labeled Processing. Its confirmed-cancel handler now updates the row to Canceled as well as the status message, giving both arms a consistent visible postcondition.
- Identical DOM content in another target, tab or URL cannot reuse a look or selection. Browser identity now participates in look hashes, full fingerprints and scoped fingerprints. This closes a potential cross-tab binding gap found in final review; it has targeted offline regression and mutation coverage.
- Visible OBO actions activate the exact resolved target before obtaining fresh selection evidence. Pure look and verification remain read-only. This has offline regression coverage; live OBO remains skipped.

The semantic contract follows Driver's distinction between collection completeness and layout visibility. A snapshot's `unknown` layout count is reported; an executable control still needs proven layout and its declared action capability. New snapshots invalidate old refs. See the [official Driver semantic snapshot contract](https://github.com/trycua/cua/blob/main/docs/content/docs/reference/cua-driver/browser-semantic-snapshots.mdx). The scoped Codex approval keys are documented in the [official config reference](https://learn.chatgpt.com/docs/config-file/config-reference).

## Remaining opportunities

- Driver can reduce facade-internal reads by returning record-scoped control relationships directly with a stable exact binding; the current unlabeled-row search is bounded but can take several semantic reads.
- Its semantic serializer should keep editable shadow nodes with their proven parents or emit them explicitly as separate roots. The facade now handles the captured missing-parent shape conservatively.
- Callers still sometimes duplicate top-level expect with per-step expect or guess a confirmation phrase. Field descriptions now explain plan versus direct mode; uncertain verification must remain distinct from delivery. Further prompt/schema improvements need measured reruns rather than relaxed proof conditions.
- Browser semantic operation on the virtual display is established for these fixtures. Canvas, native widgets, file pickers and unlocked OBO require separate live coverage; OBO remains skipped at the user's request.
