# Changelog

Semantic versioning, independent of Cua Driver. Before 1.0 the tool surface may still change in minor releases.

## 0.1.0 (unreleased, integration/0.1)

### Breaking / behavior changes
- Public names lose the `cua_` prefix (#53): the MCP tools are `look` and `do` (advanced, with `CUA_TASK_ADVANCED=1`: `windows`, `observe`, `read`, `choose`, `act`, `verify`, `trace`, `finish`), no aliases, so the default path still shows exactly two tools; the MCP server is `computer-use` (was `cua-task`, `CUA task tools`), so clients see `mcp__computer-use__look` and `mcp__computer-use__do`. The `facade/` directory is now `computer_use/` and the skill directory `skills/cua-capability-dispatch/` is now `skills/computer-use/` (skill name `computer-use`). Migration: rename the client's MCP server key `cua-task` to `computer-use` and point its args at `computer_use/server.py` (was `facade/server.py`); change any allow-list or prompt that names `mcp__cua-task__cua_*` to `mcp__computer-use__*`; reinstall the skill under its new name and remove the old `cua-capability-dispatch` copy. Call-budget numbers are unchanged. Historical run logs, traces, manifests and recorded CE text keep the old names (they record what was measured); `CUA_TASK_ADVANCED`, `.venv-facade`, `experiments/facade-vs-native` and the `inference/` paths are not renamed.
- `close_tab` presses the tab's own Close button in the tab strip (AX, background, no fronting, no `allow_foreground`); zero or several matching tabs refuse `tab_close_control_not_found` / `tab_close_control_ambiguous` before any press. Cmd+W (foreground) remains only as an explicit `allow_foreground: true` fallback when the strip shows no such control (#4).
- A clean install (no `runtime.json`) now resolves to the `fleet` profile: the Jev chooser with NuExtract3 page reading, which sends page content to the configured hosted services (user decision 2026-09-30, "Jev is the default"). `local-mac` (Julia-1) stays selectable by an explicit profile, and an existing `runtime.json` without a `profile` key that names Julia-1 and no hosted endpoint stays `local-mac`. README, PROVIDERS, LOCAL-MAC, SKILL, setup and SKETCH S4.7 updated.

### Fixed
- A plan that starts with `goto`/`open_tab`/`read_pages` always answers with `summary.title` and `summary.window` (the window it ended on), in every status and even when `expect` is null; the unverified-navigation hint says the navigation was delivered and names `look(title=...)` / `do(title=..., verify)` instead of speaking of a click (#64).
- Agent browser lifecycle (#60, refs #60, CE-FACADE-009): `shutdown` stopped only the launched process, so 23 Chrome for Testing processes stayed alive and the next launch forwarded into the stale instance; the profile restored its previous session (6 tabs in the one agent window); after a navigation the Driver flags no tab active, so every goto refused `browser_tab_ambiguous`. Chrome now runs in its own process group: `stop()` is SIGTERM to the group, 3 s, SIGKILL, then any process still carrying our user-data-dir is killed by pid (also at interpreter exit); a stale instance is killed before launch (`agent_browser_recovered_stale`); `Default/Preferences` is seeded `session.restore_on_startup=5`, `profile.exit_type=Normal`, `profile.exited_cleanly=true` and the session files are deleted before each launch; the facade remembers the tab it navigated and prefers it when none is active.
- Mobile (#69): an empty device list within 15 s of the mobile-mcp child starting is asked again after 2 s (at most twice) before it is reported, and the empty-state hint says the backend had only just started; on device screens only displayed-text elements (StaticText, TextView, Text, Label, Heading) become record `lines` and page `text`, a container, group, image or icon name never does (the iOS home no longer shows `group: label-view`), while an icon or button keeps its name as its control label.

### Added
- Response budgets (#41, CE-FACADE-011): the call-budget run records the bytes of every response per scenario and call, the stage timings and the simulated settle/idle waits, and the `tools/list` sizes; `computer_use/RESPONSE_BUDGET.json` holds ceilings (measured x 1.1) with the same CE provenance rule as the call numbers, and `scripts/check_call_budget.py` prints the table and fails over a ceiling (proposed CE, awaiting the policy owner).
- Trimmed without losing a guarantee (#41, CE-FACADE-011): `untrusted_page_text` stays on every response but the fixed notice sentence only comes with the first response and with a window or page not seen before (it stays in the instructions and the `look` description); every hint is at most 240 characters and none restates the instructions (`hint_scan.py`); the `do` and `look` descriptions no longer repeat the schema, generated schema titles are dropped (tools/list 32.5 KB to 23.6 KB); a plan's `summary` carries only what is new since the look (`summary.unchanged` counts the rest); the legacy `observation.controls` lists a repeated control once with a `count`; `trace_summary` keeps at most 4 attempts.
- Latency (#41, CE-FACADE-011): a look that waited `ACTIONS_PENDING_WAIT_S` for pressable buttons and then saw the same element count skips the extra settle observation. `do` after `look` still observes once per step: the page-change guard needs a fresh observation.
- Agent onboarding (#64, CE-FACADE-010): the MCP instructions are a welcome screen (look then do, expect is the proof, look_id, one goto-look-do example, stop and ask on a refusal) with the detail in the tool descriptions; a refusal for an environment reason of the target carries `setup: [{check, status, fix, who: agent|user}]` from the matching doctor checks (once per blocker set, never on a healthy machine); empty device and window lists and every refusal reason name the next call or who to ask; a goto-first plan on the agent browser needs no `title`; `doctor --probe` also runs goto, one look and one verified do on a bundled booking page; `time_to_first_verified_do` is traced; call-budget scenarios `onboarding_first_do` (2 calls) and `onboarding_first_do_goto` (3).
- Agent browser (#60, CE-FACADE-009): `goto`, `open_tab` and `read_pages` default to one Chrome for Testing window with a profile the server owns, installed on demand, placed on the agent display and reused for the server's lifetime; `profile: "user"` on a step uses the user's own browser; `CUA_AGENT_BROWSER=auto|user`, `CUA_AGENT_BROWSER_PATH`; refusal `agent_browser_unavailable`.
- Fixed (#60, CE-FACADE-009): the agent browser could open on the user's own screen. Chrome for Testing restored the placement saved in the agent profile (`Default/Preferences` `browser.window_placement`) over `--window-position`, and the follow-up park failed. Before every launch the placement is now rewritten to the agent display's current bounds inset by 40 px (other keys kept; `Local State` copies removed); the window is verified to lie wholly inside the display as soon as it appears, else the browser is quit (SIGTERM, SIGKILL after 2 s), the saved placement deleted and the step refused `agent_browser_misplaced`; with no agent display nothing is launched (`agent_display_unavailable`, also in `auto`; only an explicit `CUA_AGENT_DISPLAY=off` opts out). The display rect is re-read on every use, and a window that only straddles the display is no longer accepted by its centre. No call-budget number moves.
- Agent display (#60, CE-FACADE-009): windows the facade creates and windows of agent-owned apps (Android emulator, Simulator, Chrome Beta/Canary/Chromium; `CUA_AGENT_APPS`) are parked on a virtual display (`CUA_AGENT_DISPLAY=off|auto|required`, default `auto`); responses carry `agent_display` or `agent_display_note`; no call-budget number moves.
- `python -m computer_use doctor [--json] [--probe]` (read-only environment check, exit 1 on a blocker) and `bootstrap [--yes]` (builds space-mover, prefetches mobile-mcp, installs Perception, restarts the daemon with `--grant existing-profile`, edits `~/.claude.json` only with `--yes` after a backup, prints the manual System Settings steps); `scripts/setup_facade.sh` ends with doctor (#63).
- Driver 0.31 support (0.30.x still works, 0.31 not required): `timeout_ms` is sent to `get_window_state` on 0.31+, `ax_app_launching` (empty, truncated, no tokens) is a not-ready reason for the look's bounded retry and never something an action clicks against, and the stacked look wait is bounded by `LOOK_WAIT_MAX_S` (#32; the live rerun stays open).
- `goto {url, expect}` plan step: navigates the window's active tab in the user's own browser profile and is done only when the tab reports the requested page; typed stops `navigated_elsewhere`, `login_wall`, `landing_unknown`, `browser_tab_ambiguous` (CE-FACADE-007, #28).
- `open_tab {url, expect}` and `close_tab` plan steps; `close_tab` closes only the tab this facade opened (CE-FACADE-007, #28).
- A Driver refusal to attach to the browser profile is `permission_required` naming `--grant existing-profile`; the facade never switches to another browser or profile (#28).
- Call-budget scenarios `nav_goto_look_plan` (3 calls), `nav_open_tab_read_close` (3) and `nav_permission_required_stop` (1, nothing delivered), CE-FACADE-007 (#35). The `cua_do` step schema now accepts `url` for goto/open_tab (it was rejected as an extra field).
- SKILL.md and the MCP instructions: a short web workflow (goto/open_tab, look, plan, close_tab) and any refusal (`permission_required`, `foreground_required`, `pointer_not_deliverable_in_background`, `tab_close_control_not_found`) is stop-and-ask, never a reroute; the default-chooser text now matches the code (`CUA_GENERIC_PROVIDER`, else profile: `local-mac` Julia-1 / `fleet` Jev, else Jev) (#36).
- `cua_look` in a browser window also reads the page text from the Driver's `semantic_v2` snapshot, bounded (6 s per call, 10 s total, AX-only fallback with `degraded: semantic_timeout|semantic_refused|semantic_failed|semantic_empty`); DOM lines the AX tree omits appear as `dom_lines` with `sources_disagree` counts, never preferred silently and never acted on (CE-FACADE-007, #33, #29).
- `read_pages {urls (1 to 5), fields?}` plan step: one `cua_do` call opens each url in a new tab, verifies the landing, looks and closes it, returning per-page landing verdict, summary and `look_id`; a page that fails to land is reported and does not abort the others, the user's tab is never navigated (CE-FACADE-007, #34). An `open_tab` whose landing failed now leaves a tab `close_tab` can close. Call-budget scenarios `nav_read_pages_3` and `nav_read_pages_one_fails` (1 call each); no existing number moved.
- `press {menu: [exact observed path], allow_foreground?}`: an application-menu item is pressed through the Driver's `invoke_menu` (same window, path rebuilt from the observed ancestors) only when the ordinary press is refused `element_outside_target_window`, and only with `allow_foreground` (the Driver activates the window briefly); any other refusal or a non-menu control is never rerouted, nothing is filed upstream (#39, #5).
- `facade/check_protocol.py` sends `goto`, `open_tab`, `read_pages` and `press {menu}` steps through the real MCP tool schema (`PlanStep`, `extra=forbid`) and requires them to get past validation (the `url` field was once missing, so every `goto`/`open_tab` was rejected); `scripts/check_plan_mutations.py` gains wrong patches for the DOM-first look, `read_pages` and the menu route.
- Android and iOS through mobile-mcp (CE-FACADE-008, #54): `look` and `do` take `device` (an adb id or iOS simulator UDID); the server starts mobile-mcp 1.0.6 itself on first use (no setup; `mobile_backend_unavailable` without Node.js), `look(device="list")` lists devices, `look` maps the element list to the look shape (no records), `do` press/type/verify/goto bind on a fresh element list, tap by ref and verify on another fresh list (a tap that changed nothing is `screen_unchanged_after_action`, never done). Call-budget scenarios `mobile_look_do`, `mobile_ambiguous_label_stop`, `mobile_dropped_tap_stop` and `mobile_backend_missing_stop`; no existing number moved.
- Devices (CE-FACADE-008, #59): an iOS read refused `mobile_device_agent_missing` installs mobile-mcp's agent once (`npx -y mobilecli@1.0.16 agent install --device <id>`, bounded; a failure names that command) and retries once; device looks derive `records` from element geometry (vertical banding, a record needs a control) so `where.lines` works on a device with the window rules (refused `where_not_supported_on_device` only when the look found no records); real iOS home-screen fixture; scenario `mobile_where_lines` (2 calls, no existing number moved). The live tap check stays open.

- Agent display (#60): `computer_use/spaces/space-mover`, a small Swift helper (built on demand with `xcrun swiftc`), creates a headless virtual display through the private `CGVirtualDisplay` classes (`display serve`; the display lives while the helper runs) and parks a window on it by setting its accessibility position (`move --window-id --display`, verified by bounds); a Mission Control drag (`--space`) is the fallback. Live on macOS 27.0: a Chrome window parked there was driven by `look`/`do`, an AX press and a foreground pixel press from the user's screen, and the prior frontmost app was restored. `computer_use/spaces_client.py` wraps it with typed errors. See docs/SPACES.md.

### Removed
- The unqualified Qwen chat-completion vision fallback in `workers/visual_worker.py`: without `CUA_SYSTEMONE_URL` the visual provider is unavailable, nothing is sent, verification ends unverified and visual choose defers (#8).

- Deep-test fixes, live on real Chrome with Driver 0.30.4 and 0.31.0 (#50, #51): plain buttons are no longer treated as toggles (Chrome's `selected:false`); a window's first look waits for a still-growing AX tree and for page buttons Chrome has not made pressable yet, and an action step re-observes once before clicking; a capture-bound (canvas) click sends its window only in `target` (Driver 0.30.4 refused every canvas press otherwise); `close_tab` retries once on a settling window; a page that does not load is `navigate_failed` and only consent codes are `permission_required`; the menu route recognises the Driver's exit-1 form of `element_outside_target_window`; the DOM look counts only displayed-text roles and reports `semantic_not_prepared` before any navigation has prepared the browser endpoint.
- A read-only Driver call that fails as if the session were gone re-runs `start_session` once and is retried once (`driver_session_restarted` in the trace); a mutating call is never retried. A failed call reports `{tool, exit_class, session_restart_tried, driver_code}`, where `driver_code` is the Driver's own stdout code on exit 1 (for example `invalid_action_target`), and never any other Driver text. Live check: a daemon restart does not actually drop the session, so this is a bounded defence, not the cause of #30 (#31, #30).
- A Driver answer with `effect: "refused"` (top level or on any action) is a refusal with the Driver's code, never `delivered` (#38).
- `cua_look` counts only the page, not the browser's menu bar, on windows without a web area: native windows keep the AXWindow subtree minus the menu bar, title-bar buttons and off-window elements (toolbars stay), so a drawn canvas such as an Android emulator reaches Perception (#27).
- noVNC in a browser tab (#56): a page that is one canvas plus noVNC markers is `surface: novnc` in `look`; a press on a drawn label maps its Perception region into the bound tab's viewport CSS px and goes through `browser_click` (background, exact point, no `allow_foreground`), verified on a fresh capture. `viewport_mapping_unavailable` when the capture scale is not provable, `credentials_required` on a password prompt (a VNC password is never typed), `novnc_typing_unavailable`. Fakes only; not run against a live noVNC page.
