## Guidance-isolation correction before the replacement primary batch

The first workspace-write batch was stopped after 14 complete rows (terminal/web and one VNC pair). Native traces revealed local skill reads. Investigation found a harness mistake: `--ignore-rules` disables exec-policy `.rules`, not global `AGENTS.md`. The user’s global computer-use guidance was therefore still injected even with skill discovery disabled. That asymmetrically added OH guidance and file-reading overhead to some native runs. This is experiment contamination, not evidence of inferior native tool compliance. All 14 rows, their failures and the interrupted next trace remain in the preliminary archive; none is mixed into the replacement primary table.

The corrected launcher sets `project_doc_max_bytes=0` for both arms, as documented in the [official config reference](https://learn.chatgpt.com/docs/config-file/config-reference). A live canary probe in a disposable directory verified the distinction: with the normal 32768-byte budget the agent returned the injected `AGENTS.md` marker; with zero it returned `ABSENT`. Neither probe used tools. Global user configuration and AGENTS.md files were not edited. The complete seven-task, three-repetition suite is restarted under this corrected launcher with the same frozen runtime, fixtures, objectives and 240-second limit. Preliminary results remain useful friction evidence but are not clean comparative timing/token evidence.
