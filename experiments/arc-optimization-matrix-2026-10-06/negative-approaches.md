# Structural reuse and notification wake experiments

The conservative structural reuse prototype does not improve this owned native form. A randomized control measured 36 scored triples after six warmups: full fresh reader 4.954 ms, identical fresh `_node` override 4.907 ms, retained child lists 5.139 ms. Retaining topology lost a paired median 0.268 ms against the full reader and 0.224 ms against the override. It won 9/36 and 13/36 pairs respectively. All three arms made identical native AX API calls, compared every published element field and normalized parent relationships, and passed real rename, value change without explicit notification, same-count replacement, and disabled-control adversaries. The initial apparent 10.89→6.22 ms gain was not reproducible and is excluded from optimization claims. This prototype reduces no AX IPC; no native Cua port or PR is warranted on this evidence.

Source: `structure.py`, controlled runner: `structure_static.py`, raw evidence: `structure-static-results.json`. Latest Arc 74ffae1108b1cb4b1f6b161084af12646f544ba5; actual public server versions verified before the microbenchmark. This is an Arc retained-topology microbenchmark, not a Cua speed claim.

Notification wake source uses a condition variable and monotonic generation as an advisory signal from the existing activation observer, after restoration requests have been issued. It retains the original polling fallback and whole observation horizon. It returns early only after fresh native observation detects the same actual front-process or window change as before. Three detector owners force real signal delivery, delayed changes without notifications, and a spurious activation storm. A hint-as-success mutant fails the storm owner. Current a2 complete platform-macos unit gate passed 471 tests with six desktop owners ignored; this is not cross-platform certification.

The first real delayed-activation run at a2 retained all twelve trials: both arms submitted exactly once and requested activation after 400 ms, but every owned sentinel active-state-at-return oracle was false. Baseline median 1.242 s, wake 1.207 s; this is unqualified because the focus oracle failed in both arms and callback execution was not proven. Long-lived NSWorkspace frontmostApplication was stale in setup; its reads are not independent OS focus proof. The next runner uses a separate short-lived process for fresh OS foreground, plus both owned AppKit active flags and callback debug receipts. CLI logging uses CUA_LOG. These source-a2 runs became historical when upstream advanced to 45775; no current optimization conclusion is drawn.

Two initial setup-only attempts stopped before mutation. An a2 diagnostic was interrupted when parent prohibited any new outdated pair. Cleanup hardened so restore failure cannot skip fixture closure. No production daemon changes, screenshots, private app trees, or credentials are retained. The very first run did not record fresh original foreground, so its cleanup cannot claim restoration to that prior focus. Current runner records original PID in memory only and restores with the supported public tool.

Both arms rebuilt on latest 45775a9244df4a1e33090c1377eeb2448d2eb820; upstream main SHA checked immediately before the run, Arc latest and actual Cua server versions verified. Full candidate platform-macos lib gate passed 472 tests with six ignored desktop owners. Six alternating native trials measured baseline 1.208052 s versus wake 1.221408 s. Every action submitted exactly once and requested delayed activation once. Every trial failed final focus preservation: a separate fresh Python/AppKit process reported the action fixture frontmost, and the fixture was active while the owned sentinel was inactive. The existing activation observer emitted zero callback hints and zero condition-variable wake receipts. Therefore the native experiment does not demonstrate this notification mechanism working, much less a safe gain. The owned unbundled AppKit fixture/embedded CLI context may affect notification delivery; this is a limitation of this trial, not proof that all native notifications are unusable. Neither this result nor the earlier apparent timing gain qualifies a PR.

Raw latest receipts: `wake-457-live-results.json`; binary source/hash manifest: `wake-457-build-manifest.json`; whole unit log: `wake-457-tests.log`; source diff: `wake-457.patch`. Only constant debug messages were enabled. The final cleanup used supported bring_to_front on the fresh originally observed PID, retained only in memory; `wake-focus-cleanup.json` independently confirms restoration true. Owned fixtures and daemons closed; production daemon and settings untouched. A latest-source setup-only attempt stopped before action because the new slim response omitted elements; both arms then explicitly requested full_output:true.

Conservative structural reuse is rejected on repeatable negative evidence. Scoped activation-hint wakeups remain unqualified: offline owners exercise the mechanism and protect the horizon, but the actual native callback did not execute and the focus adversary failed baseline as well as candidate. No PR for either experiment.
